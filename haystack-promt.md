
техническое задание на разработку модуля hay (Haystack)

Необходимо разработать новый изолированный модуль hay внутри текущего проекта pinecone-manager-bot. Модуль реализует умного персонального помощника в Telegram на базе фреймворка Haystack, интегрированного с векторной базой данных Pinecone для ведения сквозного контекстного диалога и работы с внешними API.

1. Структура проекта и запуск

Все новые файлы создаются исключительно в изолированной папке hay/. Существующая архитектура проекта и конфигурационные файлы остаются неизменными.

1.1. Обновление скрипта запуска

• Запуск: Запуск нового модуля осуществляется через внесение изменений в существующий файл start.bat. Создавать отдельный .bat или .ps1 файл не требуется.
• Скрипт по-прежнему должен выполнять автоматическую подготовку окружения (venv), установку обновленных зависимостей, очистку кэша и корректный перезапуск процессов.

2. Функциональные требования


2.1. Управление логикой и режимами Telegram-бота

• Включение режима Haystack: В бота необходимо добавить отдельную Telegram-команду /haystack для явного переключения пользователя на логику работы нового агента.
• Отключение режима Haystack: Необходимо реализовать команду для обратного переключения пользователя из режима Haystack в стандартный (текущий) режим работы бота.
• Состояние выбранного режима для каждого пользователя должно сохраняться в оперативной памяти бота во время его работы.

2.2. Изоляция и управление контекстом (Pinecone)

• Изоляция пользователей: Внутри PineconeDocumentStore необходимо строго настроить изоляцию контекста пользователей по user_id с помощью метаданных (аналогично текущей реализации бота).
• Агент должен извлекать историю диалога и факты из базы данных, учитывая только векторы конкретного пользователя, отправившего запрос.
• При общении агент обязан выступать в роли реального ПОМОЩНИКА, сохраняя связность ответов на основе косинусного сходства векторов.

2.3. Интеграция с моделями и внешними API (Tools)

Логика инструментов реализуется в виде кастомных компонентов Haystack (@component):
1. Инструмент анализа рынка облигаций: Обращение к бесплатному API для получения фактов о важных новостных событиях корпоративных облигаций РФ.
2. Мультимодальный инструмент («Собаки»):
	• Загрузка случайной картинки из бесплатного Dog API.
	• Модель: Для распознавания породы и генерации предыстории используется модель, уже прописанная в рабочем .env файле (LLM_MODEL). Никаких новых констант для модели в код или окружение вносить не нужно.

3. Технические ограничения и логирование

• OpenAI API: Любое взаимодействие с моделями осуществляется строго через base_url (LLM_BASE_URL), берущийся из файла .env.
• Логирование: В метод выполнения пайплайна (run) обязательно должно быть добавлено детальное логирование шагов сохранения данных. Достаточно стандартного вывода ошибок в консоль start.bat (без создания отдельных .log файлов), чтобы в консоли было точно видно место возникновения ошибки в случае сбоя при записи в Pinecone.

4. Ожидаемый результат

• Создана папка hay/ с логикой агента, инструментов и кастомного хранилища документов.
• Изменен существующий start.bat.
• В requirements.txt добавлены haystack-ai и pinecone-haystack.
• В src/bot.py интегрированы команды для переключения режимов (включая обратный переход).
